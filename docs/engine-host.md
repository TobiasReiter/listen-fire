# The engine host

The movement engine (`apps/api/src/services/movement_engine/`) runs a program. Everything outside the program goes through one interface the caller hands it, `EngineHost` (`movement_engine/host.ts`): adapters, model calls, parking, cancellation, files, user lookup, write locks and the trace. The engine imports none of these itself. Every host call is a request and an answer of plain JSON: no callback, live object, `Date` or shared array crosses (instants are ISO 8601 strings). A seam test (`movement_engine/__test__/seam_guard.unit.test.ts`) fails if an engine file starts importing host code.

## What a run is given

- **Data.** The source and its language version, a `CatalogSnapshot`, the credential ids its imports name (`credentialIds`: import name to id, beside the snapshot, never in it), the trigger event, the instant it fired (`firedAt`, an ISO 8601 string; every clock read in the run answers from it), the cost cap (`costCapMicrodollars`, absent for none) with what the run spent before this segment, and, on resume, the parked state. A run may also be handed addresses to suspend at (`suspendAt`: just before a statement, or before the k-th call a statement makes); the first flow to reach one parks there once. A `CatalogSnapshot` is the team's catalog as plain JSON: adapters and their schemas, credential names, plugins, models, and the saved files the program imports. Everything the engine knows of a plugin comes from the snapshot's `plugins`: the arguments a stage feeds it (`fedArgs`), the ones it must be handed (`requiredArgs`), what a plain call hands back (`output`, `earlierOutputs`), and whether it is `priced`.
- **A host.** The calls the engine makes while it runs.

## The host's groups

| Group | What the engine asks of it |
|---|---|
| `segment` | Open the host's half of a segment (`open({ runId?, teamId, languageVersion })` answers `{ segmentId }`); close it (`close({ segmentId })` answers what its adapter calls spent, `{ cost? }`). |
| `adapters` | Resolve an instance for a segment (`resolve`) and call it by method (`call`). The engine never holds a live adapter (below). |
| `llm` | The extraction and `AI()` client, the `extract(…)` call client, `through` stages and plugins (`transforms.invoke({ plugin, config, extractedContext, budget })`), and the judge for identity matches the engine's own rules cannot settle (`arbitrateEntities` answers `{ index: number | null, judgeUnavailable?: string }`: the candidate, or null to create, and the judge's failure message when it could not be asked). Every call is priced. |
| `park` | Persist a timer, await or suspension (`sink`; a timer's `wakeAt` is an ISO string); queue the wake for an await's key (`wake`); mint and read callbacks (`callbacks`; `mint`'s `expiresAt` is an ISO string); record and find bound counterparts (`bindings`). With no `sink`, a run that reaches a park fails: that is a dry run. |
| `control` | The cancel gate, checked at each statement and model call. |
| `files` | (File imports resolve from the snapshot's `files` only.) Turn a file into text (`resolveFileText({ file, budget })`, priced: transcription and OCR are model calls); render and store a `FILE()` artifact (`render({ content, type })`). |
| `lookup` | Map an event's actor to a team user (`@user_*`): `resolveActingUser({ teamId, triggerId?, segmentId, instance, event })`. The host asks the source instance for the event's actor candidates itself, only when the trigger does not already decide the user. |
| `locks` | Cross-run write locks (below): `acquire({ segmentId, names })` answers `{ token }`, `release({ token })` gives back exactly what that acquire took. |
| `trace` | `append({ segmentId, entries })`: the run's decision trace as it goes, one statement's new entries at a time and the rest as the segment ends, so a caller can publish it before the run settles. The whole trace is on the result either way. |

After an await park is durable, the engine asks the await's question once more itself, its WHERE included. A landing that arrived between the first check and the park woke nothing, because a wake for a key with no parked run does nothing. So when the second check finds the await resolved, the engine calls `park.wake({ adapterType, teamId, correlationKey })`; the production host queues a `wake_await` work row. When the second check cannot answer (the remote is down), the engine logs an error naming the key and leaves the run parked without a wake: the adapter's own at-least-once wake covers later landings. The known gap is a landing whose only wake arrived before the park, on a re-check that then failed. A wake that cannot be queued is logged, and the park stands.

A file is a `FileRef`: a JSON descriptor of where its bytes live, never the bytes. Its `source` names either the adapter instance that owns them (`{ adapterType, credentialId?, constructionArgs?, handle }`) or the document store (`{ store: 'document', objectUri }`). The engine only carries descriptors: it hands them to `files.resolveFileText` and gets text back, gets one back from `files.render`, and passes them through write fields. Every byte read happens on the host side: a target adapter or the file-text resolver calls `streamFileRef`, which resolves the named instance with the descriptor's credential and asks it for the bytes. The file-text resolver's reads happen outside any segment: they are not counted against the segment's call ceiling and not kept in its read memo. A parked run holds the descriptors as they are, so a resume needs nothing rebound.

### Spend

Every priced call (`llm.*`, `llm.transforms.invoke`, `llm.arbitrateEntities`, `files.resolveFileText`) takes `budget: { remainingMicrodollars: number | null }` in and answers `cost?: Array<{ source, microdollars }>` out (absent: it spent nothing). `source` is where the money went, `kind:name` (`model:claude-sonnet-5`, `service:brightdata.web_unlocker`, `plugin:fetch_url`). The engine keeps the run's ledger (`movement_engine/run_context.ts`): the budget is the run's cap less what it has spent against it (`null` with no cap), and every answer's cost is charged. A host refuses priced work past the budget by answering a refusal, `{ error: { kind: 'budget', message }, cost? }`, carrying what the call spent first; the engine charges that and raises the run's cap, `RunCostCapExceeded`, from its own figures, and suspends the run there. A plugin the snapshot marks `priced` is refused by the engine before it starts once the cap is spent. `segment.close` answers what the segment's adapter calls spent (an adapter's own model call to match a record); the engine charges it as the segment ends, so it reaches the run's figures, not the cap check inside that segment.

The production host meters each priced call under its budget (`withSpendMeter`, `lib/run_spend.ts`): the model and service clients far below the call charge the meter and check it before they start, exactly as they set the billing context's usage rows. A client past the budget throws `BudgetExhausted` (`lib/run_cost.ts`) inside the host, and the host turns it into the refusal. The meter and the billing context are host state, set around each call; the engine imports neither.

### Segments

A segment is one entry into the interpreter: a fresh run, a resume, a race settlement, a callback body. Its engine state (`RunContext`: the pin, the cancel gate, the run's id for log lines, the cross-run lock holder, the spend ledger, the host segment's id) is opened by the entry point and passed explicitly to whatever needs it. The host's half (`translation_graph/segment_scope.ts`) holds what the segment's adapter calls have read (a read memo, so a record read three times in one run is one request), how many third-party calls they made (a ceiling: `AFFINITY_MAX_CALLS_PER_RUN`, default 2000), and the pin they answer under. The production host runs every adapter call inside the segment it names (`segmentScopedCalls`). A call past the ceiling answers `{ error: { kind: 'call_ceiling', message } }`; the engine fails the run with the message, and `onError` never forgives it. A call into a segment that has closed answers an error naming it.

### Adapters

The engine never holds a live adapter. `adapters.resolve({ adapterType, teamId, credentialsId?, constructionArgs?, role, dryRun?, segmentId })` answers the instance as data: `{ instance, adapterType, supportedTriggers, capabilities, methods, walksContainers?, webhookEventTypeId?, metaRecordType? }`. `instance` is an opaque id, meaningful only within its segment; the same live instance answers to the same id. `capabilities` is what `runtimeCapabilities()` returned; `methods` lists the protocol methods the instance implements, and `iterateRelated` when it streams a traversal.

`adapters.call({ segmentId, instance, method, args })` answers `{ result }` or `{ error: { kind, message, name?, detail? } }`, with `kind` either `call_ceiling` or `adapter_error` (an adapter call carries no budget, so it is never refused as `budget`; `name` is the failure's own class name and `detail` its `{ status?, code? }`). `method` is one of the adapter protocol's methods (`translation_graph/protocol/schema.ts`), except `manifest`, which `resolve` answers, and `iterateRelated`: an async iteration never crosses, so the engine walks a traversal one `iterateRelatedPage({ …, cursor? })` at a time. `args` is the method's one JSON argument (`describe` takes `{ typeId }`; a method with no input takes `{}`). An adapter's error reaches the engine as its message, name and detail; the host logs the original (class, stack, cause) at warn with the segment and run ids. Nothing thrown on the host side is recognised by class on the engine side.

The engine holds a stand-in for each instance (`movement_engine/host_adapter.ts`) that answers each method through `adapters.call`. A rehearsed target (`dryRun`) is the host's to wrap: it captures each write into the host's write sink and remembers the ids it invented, for the segment. Both hosts keep their live instances in one table (`translation_graph/engine/adapter_table.ts`).

## Supplying a host

- **Production:** `productionEngineHost` (`translation_graph/movement/engine_host.ts`). It wires each group to Postgres, the adapter registry and the model providers. Given a run id, it bills each model call to the run. The run host reads the cost cap (`MOVEMENT_MAX_RUN_COST_USD`) once as each segment starts and passes it as `costCapMicrodollars`. Firings, resumes and callbacks build their snapshot with `runCatalogSnapshotForTeam`, which returns the snapshot and, beside it, the credential ids the run is given as `credentialIds`. Ids never go into the snapshot. A test run hands the host its write sink (`writeSink`).
- **Tests:** `makeTestHost(overrides)` (`movement_engine/test_host.ts`, host side). A test supplies only the pieces its program reaches. No default touches a network or a database. `makeFakeParkSink()` records parks in memory. A piece left out does one of three things:
  - **Throws, naming itself, when the run reaches it:** resolving an adapter (a test supplies its live fakes as `adapters.resolve`; they sit in the same table the production host keeps, and the engine reaches them through `adapters.call`), every `llm.*` client, `park.bindings`, `files.resolveFileText`.
  - **Defaults quietly:** `segment.open` answers a fresh id and `segment.close` answers nothing spent, with no memo or ceiling behind them (a test of the segment scope supplies `hostSegments`, and `segmentScopedCalls` beside its adapters); `files.render` answers a document-store descriptor whose store key holds nothing (a test that reads the bytes supplies a render that stores them); `park.wake` records each request into `overrides.wakes` (a fresh array when absent); a rehearsed write goes to `overrides.writeSink`, or nowhere; `lookup.resolveActingUser` answers `null` (a test's lookup is handed `getCandidates`, a call into its live source adapter); `control.cancel` never cancels; the trace goes only to the result unless the test hands an array (`overrides.trace`); `locks` are a fresh `InMemoryWriteLocks`, one lock session per segment.
  - **Is absent, so the run takes its no-substrate path:** without `park.sink` a park fails (a dry run); without `park.callbacks` a `callback(…)` or an await on one fails as unsupported ("needs the durable trigger-run substrate"); a snapshot that carries no files fails a file import ("no file resolver").
- **Another embedder** supplies its own object of the same shape. Every call it serves takes and answers plain JSON.

## Write locks

The engine keeps two writes from colliding at two levels.

- **Within a run:** an in-process gate serialises flows of one run (collection members, combinator arms) whose writes could find each other's records.
- **Across runs:** each effect asks `host.locks` for the names it needs (`acquire({ segmentId, names })` answers a token) and gives them back when it finishes (`release({ token })`), never holding them for the whole segment. The host keeps one `WriteLockHolder` per segment, opened at its first acquire and closed with the segment, which lets go of anything still held. A record, an edge or a binding is locked as itself. An identity write (`unique by`) locks its whole record type in the team, exclusively. So identity writes to one record type in a team run one at a time across all runs, for the length of each find-then-create.

`WriteLocks` has two implementations (`services/write_locks/`):

- **`PostgresWriteLocks`:** session-level advisory locks on a dedicated connection per segment, keyed by the team and the lock name. This is the production default.
  - **Tried, never waited on.** All parallel flows of a segment share the one connection, which runs one query at a time. A blocking lock call would stall a sibling's unlock behind it, and two runs touching overlapping records in different orders would deadlock where no flow does. So a lock is tried, and retried with backoff (25 ms doubling to 250 ms, jittered) until it is granted or the timeout passes.
  - **Timeout.** A name not granted within `MOVEMENT_WRITE_LOCK_TIMEOUT_MS` (default 60 s) fails the write with `write lock timeout: <name>`. A real cross-run deadlock surfaces this way too: Postgres cannot see it, because nobody blocks inside Postgres. It never hangs.
  - **Lost connection.** A dropped connection releases everything, which covers a process dying. Server-side TCP keepalive (30 s idle, 10 s interval, 3 probes) frees a dead machine's locks in about a minute. If nothing was held when the connection dropped, the next acquire reconnects (one warning). If something was held, the segment's writes fail with `write lock session lost: <name>` until it ends, and its release logs which names were held, since the write they guarded may have run unprotected. A connection that drops under a waiting acquire fails that acquire the same way.
  - **Sizing.** Each in-flight segment that writes holds one Postgres connection of its own, outside the shared pool. In-flight segments are bounded by the drain limit (10 by default, at most 100 per external tick) plus firings on request paths. Size `max_connections` for that.
- **`InMemoryWriteLocks`:** the same holder logic over an in-process gate. `makeTestHost` uses it, and so do test runs: a test run captures its writes instead of making them, so it must never wait on a live firing.

## Recorded debts

- **Failures still throw.** A host call that fails outright (a park that cannot be persisted, a lock timeout) throws. Only the adapter calls and the priced calls answer their failures as data; the engine does not branch on any other failure's class, so a remote host can throw a plain error with the same message.
- **Resumed segments do not heartbeat.** A timer, await or ask resume keeps the run `parked` and stamps no heartbeat. A crash mid-resume re-runs the parked step: at least once, as before.
